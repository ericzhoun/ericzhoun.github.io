## Trial / Drop-in Booking feature — spec + plan
- Goal: improve engagement by letting visitors book one **free** trial on a **specific dated session**, no account/payment upfront.
- Decisions (with user): specific dated session (reuse `class_sessions`/`bookings`), free ($0), one trial per email, CTA on schedule page, provision provisional account (mirror `guest-enroll`).
- Key architecture: add `enrollments.enrollment_type` ('standard'|'trial'); per-date capacity derived by counting `bookings` for a `session_id` vs `max_seats`.
- New backend fns: `list-trial-sessions` (public read), `book-trial` (public write). New UI: `js/trial-modal.js` + CTA in `schedule.js`.
- Risk to watch: `'home'` bookings for weekly enrollments only backfilled at session-generation time → must run `generate-sessions` backfill (Plan Task 1) or capacity undercounts.
- Deliverables: `docs/superpowers/specs/2026-08-15-trial-dropin-booking-design.md`, `docs/superpowers/plans/2026-08-15-trial-dropin-booking.md`. Awaiting user approval before Phase 2 build.
